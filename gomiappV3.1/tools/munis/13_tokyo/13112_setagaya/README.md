## 収集日

- 使った資料（区のサイト。**収集日のオープンデータはない**：東京都オープンデータカタログに世田谷区の「ごみ収集日」はなかった。2026-11-26）
  - 「資源・ごみ収集日(一覧)」の CSV（`収集曜日一覧.csv`、Shift_JIS） https://www.city.setagaya.lg.jp/02241/416.html
  - 「令和8年(2026年)版資源とごみの収集カレンダー（PDF）」 https://www.city.setagaya.lg.jp/02241/36471.html（`カレンダー_2026年版.html`）
  - 「令和9年(2027年)版資源とごみの収集カレンダー（PDF）」 https://www.city.setagaya.lg.jp/02241/27859.html（`カレンダー_2027年版.html`）
- **世田谷区の収集日は、町（丁目のまとまり）ごとに曜日で決まる**（京都市と同じ形。`calendar.py` は京都市・高知市をまねた）。
  - 資源（古紙・びん・缶）：週1回。可燃ごみ：週2回。不燃ごみ：月2回（「1回目・3回目の○曜日」か「2回目・4回目の○曜日」）。ペットボトル：月2回。
  - **祝日も収集する**。休みは年末年始だけ（令和8年度：2026年12月31日〜2027年1月3日。令和9年版カレンダーの12月・1月のページの「収集はありません」）。
- 区は、暦年（1〜12月）のカレンダーを「対象地区」ごとに41種類（1〜41）作っている。カレンダーのページに「町名丁目 → PDF（対象地区の番号）」の一覧がある。
  - **地区（130）はこの一覧のとおり**（町名丁目 118 と、まわりの町とちがう日に集める集合住宅 12。例：「都営池尻二丁目アパート（池尻2丁目3番）」）。日程は対象地区の番号（アプリでは「カレンダーの対象地区 ○」）。
  - 対象地区1〜37の曜日は CSV（町名丁目ごと、118行）。CSV の町を一覧の地区名とくらべて、**同じ番号の町はどれも同じ曜日だった**（ちがえば `calendar.py` が止まる）。
    CSV と一覧で書き方がちがうのは「大蔵5・6丁目／大蔵5～6丁目」「等々力4・5・6丁目／等々力4～6丁目」だけ（丁目の集合でくらべるので同じになる）。
  - 対象地区38〜41（集合住宅）の曜日は CSV にないので、カレンダーの PDF を見て `calendar.py` の `SPECIAL` に書いた。
  - 地区の説明は、CSV の「管轄清掃事務所」（世田谷・玉川・砧）。集合住宅は住所（「池尻2丁目3番の集合住宅（まわりの町とちがう日）」）。
- **カレンダーの PDF と自動で見くらべる**：令和9年版の PDF は、日付の数字が文字で、札が色のついた四角形なので、`calendar.py` の `pdf_days` が札の色（可燃 #e60012・資源 #008d43・不燃 #0068b7・ペット #a7d397）と位置から日付を読む。
  `元データ/…/2026年度/カレンダー/2027_<番号>.pdf` があれば、その年度の範囲（2026年12月〜2027年3月）の日を、作った収集日とくらべ、合わなければ止まる。
  令和8年版（2026年）の PDF は画像だけなので読めない（4〜11月は目で見くらべた。下の「確かめたこと」）。
  - 注意：2月のページは行が高い。「24/31」のように1マスに2日あるときは、右下の日付が日曜日の列にある（列で分けて読む）。
- 置き場所：`元データ/13_東京都/13112_世田谷区/2026年度/`（`収集曜日一覧.csv`・`収集曜日一覧.html`・`カレンダー_2026年版.html`・`カレンダー_2027年版.html`・`カレンダー/`）
  - `カレンダー/` に、令和9年版の41冊（`2027_01.pdf`〜`2027_41.pdf`、1冊 約4MB）と、令和8年版の7冊（`2026_01`・`13`・`22`・`38`〜`41`）。
- **毎年やること**：
  - 区は毎年11月ごろ、次の年のカレンダーを出す（令和9年版は令和8年11月発行）。曜日はふつう変わらないが、**年末年始の休みを `calendar.py` の `YEAR_END` に足す**（新しいカレンダーの12月・1月のページを見る）。
  - 年度は2つのカレンダー（4〜12月の年と、1〜3月の年）にまたがる。2つの年の対象地区の一覧がちがうと止まる（番号が年の途中で変わるときは `calendar.py` を直す）。
  ```
  python gomiappV3.1/tools/download_sources.py 2027 13112
  python gomiappV3.1/tools/update_year.py 2027 13112
  ```
  `download` は、収集曜日一覧の CSV と、2つの年のカレンダーのページを取る（PDF は取らない。見くらべたいときは、カレンダーのページから `カレンダー/<年>_<番号>.pdf` の名前で保存する）。

  - 「ごみ分別一覧」（2025-12-22、165品目） https://catalog.data.metro.tokyo.lg.jp/dataset/t131121d3000000001 … 区のページ「資源・ごみの分別（50音順）」（2026-07-17 更新）と同じ中身
  - 「ごみの分別方法一覧」（2024-11-30、787品目） https://catalog.data.metro.tokyo.lg.jp/dataset/t131121d0000000012
- 新しいほうを先に使い、古いほうは新しいほうにない品目（663）だけ足した。**828件**。
  同じ品目で区分がちがうもの（例：薬びん 新：資源／古：不燃ごみ、携帯電話 新：拠点回収／古：販売店など）は、新しいほうにした。
- **どちらの CSV も、見出しの「品目」と「分別区分」の列が入れかわっている**（3列目が分別区分）。`opendata.py` で直して読む。
- 分別区分 → アプリの区分：可燃ごみ→可燃、不燃ごみ→不燃、資源→資源（品名にペットボトルがあれば ペット）、粗大ごみ→粗大、拠点回収・店頭・回収ボックス→拠点、区では収集していません→×（注意に家電リサイクルとあれば 家電）。
  「拠点回収または不燃ごみ」「陶器製は不燃ごみ、プラスチック製は可燃ごみ」のような区分は、文の中でいちばん前の区分にして、文を注意（「分別：…」）に残した。
- 更新：`python gomiappV3.1/tools/update_opendata.py 13112`
