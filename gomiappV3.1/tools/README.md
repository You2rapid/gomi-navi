# ごみ出しカレンダー（gomiappV3.1）のデータと道具

全国の自治体に増やせるように、データ・道具・元の資料を **都道府県 → 自治体** の順に分けて置いています。
フォルダの名前には、全国地方公共団体コード（県は2けた、自治体は5けた）を付けます。
例：山口県＝`35`、周南市＝`35215`、下松市＝`35207`、光市＝`35210`、京都府＝`26`、京都市＝`26100`

## フォルダのきまり

```
gomiappV3.1/
  index.html                    アプリ本体（どの自治体にも共通の部分だけ）
  data/
    municipalities.js           使える自治体の一覧（ここに1行足すと、市の選択欄に出る）
    holidays.js                 祝日・年末年始（全国共通・毎年作り直す）
    35_yamaguchi/               県（県コード_ローマ字）
      35215_shunan/             自治体（自治体コード_ローマ字）
        city.js                 分別区分（名前・色・出し方）、カレンダーの表示、ルール、問い合わせ先 … 手で直す
        items.js                品目検索のデータ                                                    … 道具で作る
        calendar.js             その年度の収集日と地区の一覧                                        … 毎年、道具で作る
        towns.js                地区の検索用の町名（町名 → 地区）                                   … build_geo.py が作る（毎年 update_year.py から）
  geo/
    index.json                  県の一覧と範囲
    35_yamaguchi.json           その県の町の境目と、地区との対応（今いる場所から探す）
  tools/
    update_year.py              毎年4月：すべての自治体の収集日・祝日・地図を作り直す
    download_sources.py         毎年4月：市のサイトから新しいカレンダーをダウンロード
    update_opendata.py          オープンデータ（品目・収集地区など）を取ってきて、データを作り直す
    build_geo.py                地図（geo/）を作る
    build_lgcode.py             全国地方公共団体コードの一覧を作る（総務省の Excel から。元データ/全国/地方公共団体コード/lgcode.json・lgcode.csv。道具用で、アプリでは使わない）
    build_zip.py                全国の郵便番号一覧を県ごとに作る（日本郵便のデータ。元データ/全国/郵便番号/県別/。町名の照合用で、アプリでは使わない）
    status.py                   状況一覧（元データ/状況一覧.html）を作る
    admin.py                    状況一覧を「更新」ボタン付きで開く（このパソコンの中だけで動く http://127.0.0.1:8766/）
    check_muni.py               自治体のデータが決まった形・ルールどおりか自動で調べる（エージェントが作ったデータの検査。直すことがあると終了コード 1）
    AGENT.md                    自治体のデータを作る手順書（エージェント用）：決まり・作業の流れ・できあがりの条件・作業報告の形
    make_icons.py               アプリのアイコン（gomiappV3.1/icons/）を作る（絵を変えたいときは中の数字や色を直して実行）
    lib/                        道具みんなで使う部品（自治体の一覧の読み書き・ダウンロード・地図）
    munis/35_yamaguchi/35215_shunan/   自治体ごとの道具
      README.md                 その自治体の注意・ダウンロード元
      calendar.py               カレンダーPDFの読み取り（NEED・download・make_calendar）
      geo.py                    町の境目 → 地区の対応（town_info・extra）
      opendata.py               オープンデータから作るもの（DATASETS・build）。オープンデータを使う自治体だけ
      license.json              商用利用：使っている資料ごとの利用条件・許可が必要か・問い合わせ先
      （ほかに品目を作る道具など）
gomi/元データ/                  市の資料（このパソコンだけ。GitHub には上げない）
  全国/2026年度/syukujitsu.csv
  35_山口県/35215_周南市/
    2026年度/                   その年度のカレンダーPDFなど（毎年増える）
    分別の冊子/                 品目検索の元にした冊子
    地図/                       e-Stat の町の境目（r2ka35215.kml）など
    オープンデータ/             オープンデータのファイルと、横の .meta.json（どこから・カタログの更新日）
```

アプリは、最初に `municipalities.js` と `holidays.js` だけを読み、自治体のデータは **えらんだ自治体の分だけ** あとから読みます。
自治体が何百に増えても、スマホが最初に読むデータは重くなりません（一度開いた自治体はオフラインでも使えます）。

## 状況一覧（いまどうなっているか）

```
python gomiappV3.1/tools/status.py --web
```

`元データ/状況一覧.html` ができるので、ブラウザで開きます（ダブルクリックでも開けます）。
自治体ごとに、収集日が何年度か・品目の数・設定・今いる場所から探すの地図・元データ・道具・商用利用ができるかを表にし、
直すこと（赤）と気をつけること（黄）を下にまとめます。
`--web` を付けると、市のサイトに **次の年度のカレンダーが出ているか** も調べます（2〜3月に見ると、更新できる時期が分かります）。

### ボタンで更新する（管理アプリ）

```
python gomiappV3.1/tools/admin.py
```

ブラウザで状況一覧（http://127.0.0.1:8766/）が開き、「自治体ごと」の表にボタンが出ます。
「次の年度」は今の年度の次です（今が令和8年度なら令和9年度）。

| 場所 | ボタン | 動かすもの | すること |
| --- | --- | --- | --- |
| 表の「元データ」 | 最新をチェック | `download_sources.py <次の年度> <コード> --list`（オープンデータを使う自治体は `update_opendata.py <コード> --check` も） | 市のサイトに次の年度のカレンダーが出ているか見る（保存しない）。オープンデータのカタログの更新日も見る |
| 表の「道具」 | 令和○年度を試す | `download_sources.py <次の年度> <コード>` → `update_year.py <次の年度> <コード> --preview` | 取ってきて、読み取れるか試す。地区・日程の数と、今のデータとのちがい（なくなった・ふえた地区）を出す。**アプリのデータは変えない** |
| いちばん上 | 令和○年度に切り替える（全部） | `download_sources.py` → `update_year.py` → `check_muni.py` → `status.py` | 全部の自治体を次の年度にする。**3月1日から押せる** |
| いちばん上 | 状況一覧を作り直す | `status.py` | 表を新しくする |

アプリには1年度分の収集日しか入りません。早く切り替えると、今の年度の残りの日がアプリから消えるので、
新しいカレンダーが早く出たときは「試す」で確かめておき、切り替えは4月の少し前（3月）にします。
「試す」で読み取った結果は `元データ/…/<年度>年度/calendar_preview.json` に保存されます（アプリでは使いません）。
表の自治体の名前の下の **公開** のチェックを外すと、その自治体はアプリに出なくなります（`data/municipalities.js` に `"hidden": true` が付く。データは残る）。チェックを入れるともどります。変えたら GitHub Desktop で Commit → Push origin。ストア版に入れてよいか（手順書の決まり C2）を決めるときにも使えます。
動いている間は、ほかのボタンは押せません（1つずつ動かします）。止めるときは、admin.py を動かしている画面で Ctrl+C。
admin.py はこのパソコンの中（127.0.0.1）だけで動き、上の道具しか動かせません。ほかのサイトからは動かせません。
状況一覧をファイルのまま（ダブルクリックで）開いたときは、ボタンを押すと、動かすコマンドが出ます。
作り直したら、アプリをブラウザで確かめてから、GitHub Desktop で Commit → Push origin。
`--date=2027-04-10` のように付けると、その日に見たらどうなるかを試せます。

## 毎年4月の更新（年度の切り替え）

市のサイトに新しいカレンダーが出たら（例年2〜3月ごろ）、`gomi` フォルダで（例：令和9年度＝2027）:

```
python gomiappV3.1/tools/download_sources.py 2027
python gomiappV3.1/tools/update_year.py 2027
```

1. 1つ目で、各自治体のサイトから新しいカレンダーを探して `元データ/<県>/<自治体>/2027年度/` に保存します。
   「見つからなかったもの」が出たら、まだ出ていないか市のページが変わっています。ページを開いて手で保存してください
   （保存する名前は、その自治体の `calendar.py` の `NEED` と README.md に書いてあります）。
2. 2つ目で、収集日・祝日・地図を作り直します。読み取れなかった自治体は前の年度のまま残り、最後に名前が出ます。
   自治体を指定して作り直すこともできます：`python gomiappV3.1/tools/update_year.py 2027 光市`
3. アプリをブラウザで開いて、いくつかの地区のカレンダーを市の配布物と見くらべます
   （4月より前は、アドレスの最後に `?date=2027-04-01` を付けると、その日として表示されます）。
   自治体ごとの注意（`tools/munis/<県>/<自治体>/README.md`）も確かめます。
4. GitHub Desktop で Commit → **Push origin**

必要なもの：Python と `pip install pymupdf pykakasi`

## 自治体を増やすとき

**決まり・手順・できあがりの条件は [AGENT.md](AGENT.md)**（エージェントに任せるときも、人が作るときも同じ）。地区・町名は市の資料のとおりにし、市の資料より詳しくしない。
できたら `python gomiappV3.1/tools/check_muni.py <自治体コード>` で「直す」が0か確かめる。

1. `data/municipalities.js` に1行足す（`code`・`pref`・`name`・`slug`（ローマ字）・`yomi`）。新しい県なら `prefs` にも足す
2. `data/<県>/<自治体>/city.js` を作る（いまある自治体のものをまねる。項目は下の表）
3. `tools/munis/<県>/<自治体>/calendar.py` を作り、カレンダーの読み取りを書く（`NEED`・`download`・`make_calendar`）
   → `python gomiappV3.1/tools/update_year.py 2026 <自治体コード>` で `calendar.js` ができる
4. 品目のデータ `items.js` を作る（市の分別の資料から。1行に1品目：`[品名, 区分, 読み, 注意]`）
5. 今いる場所から探すを使うなら、e-Stat の KML を `元データ/<県>/<自治体>/地図/` に置き（区のある市は区ごとに `r2ka<区のコード>.kml`）、`geo.py` を作って `python gomiappV3.1/tools/build_geo.py <県コード>`
6. `README.md` に、ダウンロード元と注意を書いておく
7. `license.json` に、使った資料ごとの利用条件を書く（下の「商用利用」）

### city.js の項目

| 項目 | 中身 |
| --- | --- |
| `cut` | ごみを出す時刻 `[時, 分]`（地区ごとにちがうときは calendar.js の日程に `cut` を持たせる） |
| `order` | 分別区分の並び（品目検索・分別区分タブ） |
| `calOrder`・`short`・`long`・`bag` | カレンダーに出す区分の並び・短い名前・長い名前・袋 |
| `darkInk` | 色が明るく、文字を黒にする区分 |
| `outlineInk` | 白い札に黒いふちを付ける区分（市のカレンダーが白地に黒いふちの札のもの。例：光市の可燃ごみ）。`darkInk` にも入れる |
| `dayAs` | 品目の区分 → カレンダーの札の区分（例：高知市の紙類・カン…は「資源物・不燃ごみ」の日に出す。品目の「次に出せる日」に使う） |
| `regions`・`regionSuffix` | 地域で分けて地区をえらぶ市（周南市の徳山・新南陽…と「地域」） |
| `schedPattern`・`schedPick`・`schedHide` | 日程の呼び方（例：A → A日程）と、日程から直接えらぶ欄。`schedHide: true` で日程の名前を出さない（京都市のように町ごとに曜日が決まる市） |
| `hint`・`contact`・`aiCat`・`footer`・`rules` | 町名検索の例、問い合わせ先、カメラ判定の区分の読みかえ、画面下の説明（`{nendo}` は年度に置きかわる）、出し方タブの HTML |
| `cats` | 分別区分。`name`・`color`（`[ライト, ダーク]` の色、または共通の色 `--c-kaden` など）・`bag`・`page`・`how`・`ex`・`ng`・`tip` |

## オープンデータ

市がオープンデータ（CC BY 4.0 など。出典を書けば商用でも使える）を出しているものは、オープンデータから作ります。
いまは次のとおりです（2026-11-21）。

| 自治体 | 収集日 | 品目 | 今いる場所（地区の分け方） |
| --- | --- | --- | --- |
| 周南市 | 市のPDF（オープンデータなし） | **オープンデータ**「ゴミの分別方法一覧」 | e-Stat の町名 → カレンダーの町名 |
| 下松市 | **オープンデータ**「ゴミ収集カレンダー」（市のPDFと見くらべる） | **オープンデータ**「ゴミの分別方法一覧」 | **オープンデータ**「ゴミ収集地区一覧」 |
| 光市 | 市のPDF（オープンデータなし） | 冊子を OCR（オープンデータなし） | カレンダーの住所 |
| 京都市 | 市の町名別一覧表PDF（オープンデータなし。曜日で決まる） | 市のページの品目を手で（オープンデータなし） | e-Stat の町名 → 一覧表の町名 |

```
python gomiappV3.1/tools/update_opendata.py            ← 最新のオープンデータを取ってきて、品目などを作り直す
python gomiappV3.1/tools/update_opendata.py --check    ← 取ってきて、カタログの更新日を見るだけ
```

- 使うオープンデータと作り方は、自治体ごとの `opendata.py`（`DATASETS` と `build`）。収集日のオープンデータは `calendar.py`（毎年の更新で使う）。
- **古くなっていないか**：状況一覧の「商用利用」の列に、オープンデータを使っているものが出ます。
  `--web` を付けると、カタログで新しくなっていないかも調べます。長く更新されていないもの（ふつうは2年。`old_days` で変えられる）は黄色の注意になります。
  市の冊子やカレンダーより古いと分かったら、市の資料に戻すか、市にオープンデータの更新をお願いします。
- オープンデータに間違いが見つかることもあります（下松市の令和8年度は、収集日の CSV に東地区 8/31 の燃やす袋ごみが抜けていた）。
  下松市の収集日は、毎年 市のPDFと見くらべ、違う日は PDF に合わせて一覧に出します。

## 商用利用（license.json）

将来、商用（広告・有料版・企業への提供など）にすることを考えて、自治体ごとに **使っている資料の利用条件** を
`tools/munis/<県>/<自治体>/license.json` に書いておきます。状況一覧の「商用利用」の列に出ます。

| 項目 | 中身 |
| --- | --- |
| `確認した日` | 市のサイトで利用条件を確かめた日。**1年たったら確かめ直す**（状況一覧で黄色になる） |
| `商用利用` | 自治体全体の判定（下の4つのどれか。いちばんきびしいデータに合わせる） |
| `データごと` | 収集日・品目・区分の説明と出し方・今いる場所などのデータごとに、**使っている情報**（アプリで何を使っているか、具体的に）・元にした資料・利用条件・判定・オープンデータから作っているか・メモ |
| `オープンデータを使っている` | オープンデータから作っているデータの名前 |
| `オープンデータ` | その自治体のごみのオープンデータ（`使っている`：アプリで使っているか） |
| `サイトの利用条件`・`オープンデータの方針` | 市のサイトの著作権のページと、オープンデータのページ |
| `許可の問い合わせ先` | 許可をもらうときに連絡する課 |
| `出典表示` | アプリに書く出典の文 |
| `許可の記録` | 市に問い合わせた結果。`{"日付": "2027-01-10", "相手": "○○課", "結果": "許可", "条件": "出典を書く", "メモ": ""}` のように足す |
| `やること` | 商用にする前にすること |

判定の4つ：

| 判定 | 意味 |
| --- | --- |
| `可` | そのまま商用で使ってよい |
| `出典表示で可` | 出典（と、加工したこと）を書けば商用で使ってよい。オープンデータ（CC BY 4.0）や e-Stat など |
| `要確認` | 市のサイトに利用条件が書かれていない。市に聞く |
| `要許可` | 市のサイトで「許可なく使用・転載・販売などは禁止」とされている。市の許可が必要 |

状況一覧の「直すこと・気をつけること」はクリックすると、どうすればよいかが開きます。商用利用の項目（表の「商用利用」をクリックしても開く）には、
許可が必要な情報の一覧・市のきまり・問い合わせ先・問い合わせの例文（「文を写す」ボタンつき）が出ます。

市から許可をもらったら、`許可の記録` に書き、そのデータの `商用利用` を `可`（または `出典表示で可`）に直し、全体の `商用利用` も直します。

どの自治体にも共通の資料：

| 資料 | 利用条件 |
| --- | --- |
| e-Stat 国勢調査の町丁・字等別境界データ（今いる場所から探す） | e-Stat の利用規約（政府標準利用規約に準拠）。出典表示で商用可 |
| 内閣府「国民の祝日」CSV（祝日） | 内閣府のサイトの利用規約（政府標準利用規約に準拠）。出典表示で商用可 |
| MobileNet v2・TensorFlow.js（カメラで調べる） | Apache License 2.0。商用可（ライセンスの表示を残す） |

> この表は、市のサイトに書かれていることをまとめたものです。法律の判断ではありません。商用にする前に、各市に問い合わせて確かめてください。

## たまにしか変わらないもの

- **分別の冊子**（品目検索）：自治体ごとの README.md に作り方があります。改定されたら Claude に頼んでください。
- **町の境目の地図**：国勢調査（5年ごと）の新しい境界データが出たら、各自治体の `地図/` の KML を差しかえて `python gomiappV3.1/tools/build_geo.py`
- **郵便番号**：日本郵便のデータは毎月末ごろ更新。`python gomiappV3.1/tools/build_zip.py --download` で最新を取ってきて `元データ/全国/郵便番号/県別/` を作り直す（状況一覧の「住所」の列と、京都市の町名の照合に使う）
